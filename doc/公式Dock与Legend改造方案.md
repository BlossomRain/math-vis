# 公式 Dock 与 Legend 改造方案

> 目标：让用户可以同时进行“看图、调参、看公式、看图例”，并且不压缩主画布，不影响截图工作流。

---

## 1. 问题背景

当前版本已经有：

- 主画布
- 参数控制
- 观察面板
- 关键点面板
- 用户函数对比
- 说明与推导

但“说明与推导”现在放在右侧最下方，会带来几个问题：

- 阅读路径太长，调参数时需要频繁上下滚动
- 公式与图形距离太远，无法形成同步观察
- 截图前如果只想临时看推导，不够顺手

另外，当前页面还缺少统一的 `legend` 图例说明，用户需要自己猜颜色、点、线、弧分别代表什么，不利于教学和截图后二次使用。

---

## 2. 设计目标

本轮改造聚焦两个能力：

1. 让“公式 / 推导”变成可按需打开的辅助阅读层，而不是固定堆在页面底部
2. 增加 `legend` 图例，让颜色、线型、关键对象的语义一眼可见

具体目标：

- 主画布优先，不被长期遮挡
- 参数调整时，公式和图形可以同时观察
- legend 必须足够轻，不抢主内容
- 支持截图前快速关闭辅助信息
- 后续可扩展到更多章节页面

---

## 3. 推荐方案

推荐采用：

- `右侧 Dock Panel` 承载公式与推导
- `画布内角落 Legend Card` 承载图例

这是当前项目里最平衡的一种方式。

### 3.1 公式展示：右侧 Dock Panel

交互方式：

- 在画布右上角或侧栏顶部增加按钮：`公式`
- 点击后，从右侧滑出一个 Dock Panel
- Dock 默认悬浮在主画布右侧区域，不占据文档流底部
- 可关闭、可折叠、可固定

推荐状态：

1. `关闭`
- 只显示按钮，不显示面板

2. `展开`
- 显示完整公式与推导
- 适合一边调参一边看

3. `折叠`
- 保留一个窄标签条，例如 `公式`
- 点击后再展开

### 3.2 图例展示：画布内 Legend Card

交互方式：

- 在画布左上角或右上角放一个小型 `Legend Card`
- 默认显示
- 支持一键隐藏
- 截图模式默认隐藏，或由用户主动开启

Legend 只负责解释“图上元素是什么意思”，不承载推导内容。

---

## 4. 为什么不推荐其他方案

### 4.1 不推荐底部说明区

问题：

- 会明显压缩画布高度
- 单位圆、函数波形都会变得更难观察
- 页面继续加内容后，滚动会越来越重

### 4.2 不推荐居中弹窗 Modal

问题：

- 遮挡图形
- 调参数时必须来回开关
- 不适合“持续阅读 + 持续观察”的场景

### 4.3 不推荐纯 Tooltip / Popover

问题：

- 只适合短说明
- 不适合承载分步推导、LaTeX、大段解释

---

## 5. 页面结构建议

改造后建议的页面结构：

```text
主页面
  左侧：目录导航
  中间：主画布
    - 画布顶部工具按钮
    - 画布内 Legend Card
    - 关键几何对象 / 函数图像
  右侧：常驻教学侧栏
    - 参数控制
    - 观察
    - 关键点
    - 用户函数对比
  悬浮层：公式 Dock Panel
    - 核心公式
    - 推导步骤
    - 当前参数下的对应数值
```

说明：

- 右侧侧栏继续承载高频操作与高频观察
- 公式推导从“常驻底部信息”改为“按需展开的阅读层”
- legend 直接靠近图，降低理解成本

---

## 6. Legend 设计方案

## 6.1 Legend 的职责

Legend 只做一件事：

把图上的视觉编码翻译成语义。

例如：

- 绿色线段：`OA`
- 粉色线段：`OC`
- 绿色点：`A = (cos a, sin a)`
- 粉色点：`C = (cos(a+b), sin(a+b))`
- 绿色圆弧：角 `a`
- 橙色圆弧：角 `b`
- 虚线圆弧：角 `a+b`

在叠合公式页中：

- 蓝色曲线：`a cos x`
- 橙色曲线：`b sin x`
- 绿色曲线：`a cos x + b sin x`
- 紫色竖线：观察位置 `x0`
- 点 `Pc / Ps / P`：当前采样点

## 6.2 Legend 的内容形式

推荐每一项采用：

- 小色块 / 小线段 / 小虚线段 / 小圆点
- 对应标签
- 可选的短说明

例如：

```text
[绿色实线] OA
[粉色实线] OC
[绿色圆点] A = (cos a, sin a)
[橙色圆弧] b
[虚线弧] a+b
```

## 6.3 Legend 的布局建议

推荐采用紧凑卡片：

- 宽度 `180px - 240px`
- 位置：画布左上角优先
- 半透明背景
- 不要太厚重

原因：

- 左上角通常不压到函数峰值区域
- 用户阅读路径是“先看图，再扫一眼图例”

## 6.4 Legend 的显示规则

建议：

- 默认显示关键图例
- 只显示当前可见对象
- 用户关闭某条系统对象时，Legend 同步隐藏该条
- 截图模式默认隐藏

---

## 7. 公式 Dock 设计方案

## 7.1 Dock 的职责

Dock 负责承载：

- 核心公式
- 分步推导
- 与当前参数联动的数值观察

它不是普通说明区，而是“教学阅读面板”。

## 7.2 Dock 的推荐结构

顶部：

- 页面标题
- 关闭按钮
- 固定 / 折叠按钮

中间采用 Tabs：

1. `公式`
- 展示本页核心公式
- 用于快速确认本页目标

2. `推导`
- 分步展示推导过程
- 每一步用单独卡片

3. `联动观察`
- 展示当前参数下的替换结果
- 与右侧观察面板形成补充，不必完全重复

## 7.3 Dock 内容建议

### 欧拉与和角公式页

`公式` Tab：

- 欧拉公式
- 和角公式最终结果

`推导` Tab：

- `e^{i(a+b)} = e^{ia}e^{ib}`
- 展开复数乘法
- 比较实部与虚部

`联动观察` Tab：

- `sin(a+b)`
- `sin a cos b + cos a sin b`
- 两者误差
- `cos(a+b)`
- `cos a cos b - sin a sin b`

### 叠合公式页

`公式` Tab：

- `a cos x + b sin x = R sin(x + \varphi)`

`推导` Tab：

- 展开右边
- 比较系数
- 得到 `R` 与 `\varphi`

`联动观察` Tab：

- 当前 `a cos x0`
- 当前 `b sin x0`
- 当前和函数值
- 当前 `R sin(x0 + \varphi)`
- 误差

---

## 8. 推荐交互细节

### 8.1 顶部工具区按钮

建议在画布顶部增加：

- `Legend`
- `公式`
- `截图`

其中：

- `Legend` 控制画布内图例显示
- `公式` 控制 Dock 开关
- `截图` 保留现有导出能力

### 8.2 截图模式规则

截图模式下建议：

- 默认隐藏 Dock
- 默认隐藏 Legend
- 允许用户手动开启 Legend 后截图

原因：

- 大部分截图只想保留干净主图
- 少部分教学截图会需要图例，可以保留开关

### 8.3 页面记忆状态

建议记录以下 UI 状态：

- Dock 是否打开
- Dock 当前 Tab
- Legend 是否显示

这样用户切换页面后再回来，不需要重新调整。

## 9. 与当前项目结构的适配方案

推荐新增以下组件：

```text
src/components/overlay/
  FormulaDock.tsx
  FormulaDock.css
  LegendCard.tsx
  LegendCard.css
  CanvasToolbar.tsx
```

推荐的数据输入方式：

### 9.1 Legend 数据

不要从画布对象“临时猜测”文案，建议每个页面模型显式提供 legend 数据。

建议新增模型字段：

```ts
legendItems: LegendItem[]
```

结构建议：

```ts
interface LegendItem {
  id: string
  label: string
  kind: 'line' | 'dashed-line' | 'point' | 'arc' | 'curve'
  color: string
  visible?: boolean
  description?: string
  objectId?: string
}
```

这样做的好处：

- legend 文案可控
- 不依赖渲染对象反推语义
- 适合教学页面精细表达

### 9.2 公式 Dock 数据

同样建议由页面模型显式提供：

```ts
formulaDock: {
  formulas: FormulaCard[]
  derivations: FormulaCard[]
  insights?: FormulaCard[]
}
```

结构建议：

```ts
interface FormulaCard {
  id: string
  title: string
  latex: string
  note?: string
}
```

好处：

- 页面内容独立维护
- 以后新增章节时，直接填配置即可
- 模板组件保持通用

## 10. 页面级内容建议

## 10.1 欧拉与和角公式页

legend 最少应包含：

- 单位圆
- `OA`
- `OC`
- 点 `A`
- 点 `C`
- 角 `a`
- 角 `b`
- 角 `a+b`

Dock 最少应包含：

- 欧拉公式
- 和角公式最终结果
- 实部 / 虚部比较

## 10.2 叠合公式页

legend 最少应包含：

- `a cos x`
- `b sin x`
- `a cos x + b sin x`
- `x0`
- `Pc`
- `Ps`
- `P`

Dock 最少应包含：

- 目标公式
- 比较系数
- `R` 和 `phi` 的来源

## 11. 实施优先级

建议按下面顺序做：

### P1

1. 增加 `Legend` 开关按钮
2. 增加画布内 `LegendCard`
3. 将现有“说明与推导”改造成 `FormulaDock`

### P2

4. Dock 增加 `Tabs`
5. Dock 增加“联动观察”页签
6. 记忆 Dock / Legend 状态

### P3

7. 截图模式支持“带图例导出”
8. 不同页面支持不同布局预设

---

## 12. 结论

本项目当前最适合的方案不是继续往右侧底部堆信息，而是分层：

- `Legend` 负责解释图上对象
- `Dock` 负责承载公式与推导
- `右侧常驻侧栏` 负责参数、观察、关键点和用户对比函数

这样能同时满足：

- 看图
- 调参
- 看公式
- 理解颜色和对象含义
- 快速截图

并且对后续“微积分 / 预备知识 / 连续 / 导数 / 积分”等页面都具备可复用性。
